MCP · 멀티에이전트 · 개인 프로젝트 · 2026.05 ~ 10SyncAI — LLM이 사용자 PC의 파일을 다루는 협업 도구

팀원마다 AI를 다르게 써서 코드가 충돌하던 경험에서 출발했습니다. 채팅방에서 /ai로 요청하면 계획을 세우는 LLM과 실행하는 LLM이 나눠 일하고, 실행은 사용자가 허락한 PC 폴더 안에서만 일어납니다.

채팅 /ai 요청팀 채팅방에서 작업 요청
↓
Supervisor LLM무엇을 할지, PC나 외부 앱이 필요한지 판단
↓
사용자 확인할 일을 먼저 보여 주고 승인받음
↓
Worker LLMFunction Calling으로 도구 호출, 최대 20회 반복
↓
MCP 클라이언트 (백엔드)도구 목록 조회와 실행 요청
⇅ WebSocket
MCP 서버 (사용자 PC)JSON-RPC tools/list, tools/call · 파일 도구 11개

외부 앱(Notion 등)은 Composio 도구로 같은 흐름에 붙였습니다.

왜 PC가 먼저 연결하나

사용자 PC는 방화벽과 공유기 뒤에 있어 서버가 먼저 들어갈 수 없습니다. 그래서 PC의 MCP 서버가 백엔드로 WebSocket을 먼저 열고, 끊기면 간격을 늘려 가며 다시 붙도록 했습니다.

LLM의 실행 범위 제한

사용자가 고른 폴더 밖 경로, 홈 디렉터리 참조, 민감한 경로와 확장자는 서버에서 막습니다. 연결은 토큰으로 인증하고, PC나 외부 앱에 접근하는 작업은 실행 전에 사용자 확인을 받습니다.

만든 것과 한계

FastAPI, Next.js, PostgreSQL로 만들어 Fly.io에 배포했고 PC용 설치 스크립트도 만들었습니다. 커밋은 321개입니다. 다만 시장 출시와 사용자 확보까지는 하지 못했습니다.

RAG · 2-LLM · 산학과제 · 2인 팀 · 2026.04 ~ 06CAPD — 복막투석 환자 기록 검토와 AI 후속 질문

서경대 SW인재양성 프로그램의 기업 산학과제입니다. 환자가 남긴 일일 기록을 바탕으로 AI가 후속 질문과 임상 요약을 만들고, 의사가 검토합니다.

역할 분담 (공식 기여도 50:50)
팀원: 프런트엔드(React 전체 UI), DB 스키마, UI/UX 설계
본인: 백엔드(FastAPI REST API 전체), AI 파이프라인, GCP 인프라(Cloud Run 3개, Cloud SQL, Secret Manager, CI/CD), 테스트 자동화

실패에서 나온 2-LLM 구조

처음에는 LLM 하나에 수치 계산과 해석을 모두 맡겼는데 계산 오류가 반복됐습니다. 계산은 Python이 맡고, 첫 번째 LLM은 검색용 질의를 만들고, 두 번째 LLM은 검색된 근거로 환자 질문을 만들도록 나눴습니다. 첫 번째 단계가 실패하면 단일 LLM 경로로 자동 전환됩니다.

근거를 붙이는 RAG

KDIGO, ISPD 가이드라인과 MedlinePlus를 1,012개 청크로 나눠 pgvector에 넣고, 여러 질의로 검색합니다. MedlinePlus는 주 1회 자동으로 갱신됩니다.

사람이 마지막에 확인

AI가 만든 질문은 검토 대기 목록에 쌓이고, 의사가 확인하거나 거절합니다. 환자 기록은 SOAP 형식 임상 요약과 위험도(정상, 주의, 긴급)로 자동 정리됩니다.

기다리지 않는 응답

질문 생성 시간과 화면의 확인 주기가 맞지 않아, 폴링을 서버가 바로 보내는 SSE 스트리밍으로 바꾸고 팀원과 응답 형식을 다시 맞췄습니다.

JOYHILL 교회 청년부 출석·커뮤니티

React, Spring Boot, PostgreSQL로 만들어 GitHub Actions로 AWS EC2에 배포합니다. 등록 계정 217명, 5단계 역할 기반 권한, 커밋 331개와 머지 PR 52개. 교인 약 1,000명이 쓸 새 앱은 별도 저장소에서 개발 중이며 테스트 273개로 정책을 검증합니다.

QTPot QT 인증 관리

React + TypeScript, Spring Boot, MySQL로 만든 앱입니다. 가입 46명 중 32명이 인증했고, 누적 인증은 956회입니다.
운영 중 생긴 문제원인을 찾아 고친 방법
자동 로그인이 규칙 없이 풀림로그인부터 토큰 갱신, 저장까지 흐름을 따라가 보니 약 20곳에 복사된 갱신 코드가 새 토큰을 덮어쓰고 있었습니다. 한 모듈로 모아 해결했습니다.
사진 업로드 실패 (413 → 500 → 502)nginx 업로드 한도, S3 접근 권한, 재시작 직후 기동 지연을 하나씩 구분해 해결했습니다.
세션 만료 후 에러 화면에 갇힘인증 실패가 403으로 떨어져 401 자동 로그아웃이 동작하지 않아, 두 처리를 분리했습니다(QTPot).
