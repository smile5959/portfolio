01

Readle · 근거의 순서로 설득한 기획

2026.09 교내 해커톤(SKTHON·GovTech)6인 팀 PO대상

학생 문해력 학습 서비스를 기획했습니다. 제가 맡은 일은 문제 정의, 자료 조사, 사업 모델, 발표입니다. 아이디어를 말로 설득하지 않고, 심사위원이 물을 질문 순서대로 근거를 쌓았습니다.

1 · 문제는 얼마나 큰가
PISA 읽기 501점
참여 이래 최저, 이전 515점 대비 14점 하락
2 · 해결 방식은 효과가 있나
효과크기 0.499
학생 48,478명 퀴즈 학습 메타분석, 읽기·어휘 0.644
3 · 돈은 어디서 오나
3단계 사업 모델
파일럿 효과 데이터 → 교육청·학교 도입
배운 점 · 좋은 기획은 아이디어보다 근거의 순서에서 나왔습니다. 사업계획이나 투자 검토 자료를 만들 때도 문제의 크기 → 해결 방식의 근거 → 수익 구조 순서로 정리하겠습니다.

해커톤 기간 안에 실제 사용자 인터뷰는 하지 못했습니다. 발표에 쓴 사용자 페르소나는 조사 자료를 바탕으로 만든 가상 인물입니다.

JOYHILL · 숫자를 직접 관리하며 운영한 서비스

2026.03 ~ 운영 중기획부터 운영까지 1인등록 계정 217개

다니는 교회 청년부의 출석은 앱시트와 구글 스프레드시트로 관리했는데, 둘 사이의 동기화 오류가 반복되었습니다. 출석·공지·조직 관리를 하나로 묶은 웹 서비스를 AI 도구를 활용해 직접 기획하고 만들어 2주 만에 실제 데이터로 운영을 시작했습니다.

쓰는 사람이 계속 쓸 수 있게 했습니다

  • 운영진이 익숙한 스프레드시트를 계속 쓰도록 출석 통계를 매일 새벽 자동으로 시트에 백업. 실패가 성공처럼 보이지 않게 성공했을 때만 시각을 기록
  • 백업이 낮 12시에 돌던 것을 발견해 서버 시간대 문제를 한국 시간으로 수정
  • 역할마다 쓰는 기능이 달라 질문이 늘자 역할별 10쪽 사용 가이드를 만들어 공유

의견이 다른 사람들을 모아 결정하게 했습니다

장년층에서도 같은 서비스를 쓰고 싶다는 요청이 와, 교인 전체(약 1,000명)로 넓히는 작업을 하고 있습니다. 권한과 조직 구조처럼 사람마다 생각이 다른 쟁점을 목록으로 정리해 교회 회의를 직접 기획하고 진행했고, 결정된 내용은 서비스 규칙으로 고정해 다시 흔들리지 않게 했습니다.
